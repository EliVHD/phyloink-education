# One adaptable bottleneck and recovery example

Use **Learn → Bottleneck & recovery** in the unreleased A06.2 application build recorded in [verification.json](verification.json). The [model and workflow](https://github.com/EliVHD/phyloink/blob/8f0fa15bc057634ecac8edc8133edd52a1db6705/docs/BOTTLENECK-LAB.md) describe this exact build. The authoritative usage and Teacher's Guides remain in the application repository through **Guides**. This is one finite synthetic example with adaptation choices, not a course or a continuing lesson commitment.

Start with initial/recovered **N = 100**, **100 A copies**, small **N = 5** at generations **10–19**, recovery at **20**, horizon **40**, **four trials per condition** and seed **1**. A separate constant-size condition keeps N = 100. The manual [configuration](activity.json) is not an application import format. The abstract A/a locus does not describe organisms in a supplied tree; see [model and reading limits](SOURCES.md).

1. Choose **Use bottleneck example** or enter the recorded settings manually. Predict the no-drift A frequency after recovery before running.
2. Run both conditions. Inspect generations 9, 10, 19, 20 and 40. Compare each row's N and A/a counts with its frequency rather than comparing raw counts across different N.
3. Follow a trial that loses or fixes an allele through recovery. Can increasing N recreate the missing allele? Compare with a trial retaining both alleles, whose one-locus H may rise or fall.
4. Adapt this same example: change severity, timing, duration or seed while holding other controls fixed. Conditions use separate seeded streams; matching trial numbers are not the same individuals or guaranteed counterfactual pairs.
5. Use **Create worksheet** for your own prompts/instructions. Student and teacher packages download separately; review configured references after changing wording and keep teacher notes private. No learner predictions/feedback/progress or cursor overlays are copied.

The [student handout](student-handout.pdf), [editable HTML](student-handout.html), [editable text](student-handout.txt), [native paths SVG](paths.svg), [complete counts CSV](bottleneck-counts.csv) and [context](context.json) are generated by the application's worksheet renderer. [Teacher notes](teacher-notes.md) explain exact seeded results and adaptation limits. [Manifest](manifest.json) records exact resources. Files work locally after downloading, with no account, server or remote assets. Print at 100% on A4 and review every page on the intended device. Printed tables select a few labelled generations; CSV retains every condition/trial/generation.

Each target generation resamples 2N_t copies with replacement using the previous frequency. This models reproduction, not a mortality cull or tracked survivors. Missing alleles cannot return through recovery alone. N is a model input, not an empirical estimate. H = 2p(1−p) describes gene diversity at this biallelic locus, not measured heterozygous individuals or genome-wide diversity. Locus loss/fixation is not species extinction. No mutation, migration, selection, sex structure, linked loci, pedigrees or demographic inference is added.

`activity.json` and worksheet context are documentation, not application project/scenario imports. Temporary practice resets on return to the editor; explicit worksheets retain educator setup and regenerated data. Original text/code/plots use [0BSD](LICENSE). Optional readings retain their own terms and are not bundled. Older tree packs, scenarios and lab resources retain their original bytes and verification records.

`node tools/verify-bottleneck.mjs --app /path/to/phyloink` checks exact files/hashes, the pinned build, model settings, seeded counts and worksheet roles. `node tools/render-bottleneck.mjs --app /path/to/phyloink` regenerates editable student artifacts explicitly; optional `--playwright-module /path/to/playwright/index.mjs --browser-channel msedge` also prints the PDF using an installed browser. Regeneration requires a new page review and inventory.
