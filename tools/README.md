# Optional authoring and packaging tools

For A06.2, `node tools/render-bottleneck.mjs --app /path/to/phyloink` regenerates the single example’s student HTML/text/plot/CSV/context through the app worksheet renderer. Optional `--playwright-module /path/to/playwright/index.mjs --browser-channel msedge` also prints its PDF locally. Inspect every page and refresh verification/inventory after regeneration. `node tools/verify-bottleneck.mjs --app /path/to/phyloink` checks exact resources, the pinned build, seeded counts, regeneration and audience separation. Earlier materials are untouched.

For A06.1, `node tools/render-linkage.mjs --app /path/to/phyloink` regenerates the single test-cross student HTML/text/SVG/context using the application worksheet renderer. Optional `--playwright-module /path/to/playwright/index.mjs --browser-channel msedge` also prints its PDF locally. Inspect every page and refresh verification/inventory after regeneration. `node tools/verify-linkage.mjs --app /path/to/phyloink` checks exact resources, the pinned build, probabilities, seeded counts, worksheet regeneration and role separation. These tools modify no historical materials.

For A05's adaptation workflow, `node tools/verify-worksheet-workflow.mjs --app /path/to/phyloink` verifies existing resource hashes, recorded build identity and separately generated student/teacher lab packages from the existing setups. It creates no new lesson packs and does not regenerate historical artifacts. Actual browser font measurement and review of every printed page remain required for an adapted worksheet.

For A04's two population walkthroughs, `python tools/render-population.py` (ReportLab) creates the standalone HTML/two-page PDF from its editable configuration. Inspect both pages. `node tools/verify-population.mjs --app /path/to/phyloink` verifies their exact inventory, pinned build, fixed default counts and model invariants. Existing tree and inheritance materials are not regenerated by these commands.

The two A03 inheritance walkthroughs use `python tools/render-inheritance.py` (ReportLab) to render their shared editable configuration to HTML and a two-page PDF. Inspect both PDF pages after changes. `node tools/verify-inheritance.mjs --app /path/to/phyloink` checks their exact inventory/hashes, recorded application build and model probabilities. Neither tool modifies or repackages the original tree examples. The lab configuration is documentation for manual controls, not an application import file.

Downloaded examples work without these tools. Use them only when regenerating or verifying the repository's materials.

`verify-and-package.py` uses Python's standard library, makes no network requests, verifies reviewed example contents and links, and recreates the three ZIPs and inventories. It requires the recorded browser and print checks to have passed.

```sh
python3 tools/verify-and-package.py
```

To recreate projects, supply an explicit checkout of the PhyloInk source commit recorded in verification.json. Build and serve it locally first. This optional authoring helper needs Node.js 22.18 or later, Playwright, and an installed Edge browser. Install authoring dependencies separately; they are not included in the packs or required by the app.

```sh
node tools/prepare-projects.mjs --app /path/to/phyloink --url http://127.0.0.1:4173
node tools/render-handouts.mjs
python3 tools/render-handouts.py
```

The last command needs ReportLab. `render-handouts.mjs` produces 300 dpi temporary figure PNGs with the browser; the Python helper creates printable handouts from the same activity.json. Review every rendered PDF page after any meaningful content/layout change. An optional `--playwright-module /path/to/playwright/index.mjs` argument allows an already installed Playwright module to be used without changing repository dependencies.

Prepare geometry in the browser, not only in a Node process: different JavaScript engines can produce tiny trigonometric differences that affect strict saved-scene replay. Font measurement alone is not sufficient to establish browser compatibility. Open, save and export the resulting project in the actual application before changing its verification record.

Regeneration changes document/operation identities and may change geometry with different browser fonts. Keep the resulting source/method/export records, repeat scientific answer checks, update the verification snapshot honestly, and rebuild archive inventories. Do not label an arbitrary regenerated file as reviewed just because it parses.

## Local scenario checks

`node tools/verify-scenarios.mjs` independently checks the two scenario files, their embedded-source hashes and the unchanged original ZIP/PDF hashes. Add `--app /path/to/phyloink` to run the application’s strict scenario reader from the explicitly supplied A02 checkout. Node.js 22.18 or later is required; no package installation or network requests are needed. This optional authoring path is not a dependency of the downloaded scenarios.
